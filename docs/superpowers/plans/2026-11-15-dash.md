# Clinic dash Implementation Plan

> Execute inline with superpowers:executing-plans. User instructed all necessary work without another approval cycle.

**Goal:** Implement protected /dash, separate manager/secretary login and a useful doctor workflow.
**Architecture:** Django server templates with sessions, database roles, private local document storage. PostgreSQL supported for production, SQLite for local tests.
**Tech Stack:** Python 3.12+, Django 5.2 LTS, gunicorn, psycopg, qrcode.
**Spec:** docs/superpowers/specs/2026-11-15-dash-design.md

## Global Constraints
- Existing checkout, no worktree; no remote push, hosting changes or default passwords.
- Preserve root website. All application routes/assets live under /dash/.
- Secretary has no clinical access until permissions specified.
- No unverified claims about template/production readiness.

## Review Focus
- Role bypass by direct POST/file URLs or role changes after login.
- Login CSRF, open redirects, throttling across processes, session expiry.
- Patient text escaping and search normalization; duplicate identifiers.
- File traversal, content type spoofing, public storage and upload limits.
- Existing root-site coexistence, production secrets, persistence and proxy trust.
