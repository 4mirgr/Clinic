# فهرست کامل وضعیت و کارهای باقی‌مانده — ۲۲ نوامبر ۲۰۲۶

مرجع این فهرست کد فعلی، بررسی مستقل، آزمون‌ها و تصمیم‌های ثبت‌شده مالک است؛ کارهای زیر خارج از این پروژه یا وعدهٔ فعال‌بودن سرویس ساخته‌نشده نیستند. پیش‌نمایش با هویت مشترک فعال است؛ ثبت پزشکی زنده هنوز فعال نشده است.

## انجام‌شده در این مرحله

| کار | نتیجه |
| --- | --- |
| دسترسی تقویم حساب پزشکی در ابزار گفتگو | درخواست دوباره انجام شد؛ تقویم اصلی owner، FreeBusy و ایجاد/ویرایش/حذف رویداد آزمایشی واقعاً موفق بود؛ رویداد باقی نماند. |
| عیب‌یابی تقویم پنل | وضعیت واضح تنظیم ناقص/کلید نامعتبر/حساب یا توکن ناسازگار/ساعات تعیین‌نشده/خطای سرویس و پیش‌نمایش؛ نام تنظیمات لازم بدون مقدار محرمانه. تست اتصال مدیر فقط FreeBusy است. |
| تغییر/حذف مستقیم در Google | طبق انتخاب مالک، `reconcile_calendar --probe --apply-google` تغییر رویداد متعلق به برنامه را در پنل می‌پذیرد؛ تداخل وقت، پاسخ ناشناخته و تغییر هم‌زمان بررسی می‌شوند. اطلاعات تقویم شخصی وارد نمی‌شود. اجرای واقعی job هنوز نصب نشده است. |
| بازبینی نوبت‌ها | نگهداری زمان‌ها هنگام تداخل، جلوگیری از retry نامناسب و چرخش بررسی‌ها برای نادیده‌نماندن نوبت‌های بعدی. مدیر دکمه دریافت تغییرات دارد. |
| یک حساب برای همه ورودی‌ها | همان پروژه Auth مشترک حفظ شد؛ هیچ مرجع یا ثبت‌نام دوم ساخته نشد. ابزار اپراتوری حل تعارض حساب محلی قدیمی، با تأیید UUID/نقش و اجرای آزمایشی پیش‌فرض ساخته شد. |
| تاریخچه کامل ویرایش کتابخانه توصیه | نسخه‌های ویرایش، منبع، برچسب و تأیید در ذخیره عادی حفظ می‌شوند؛ snapshot تحویلی بیمار ثابت می‌ماند. تاریخچه فقط پزشک است. |
| بررسی آمادگی و عملیات | `check_clinic_readiness`، runbook زمان‌بندی و تمرین رمزنگاری/بازیابی داده ساختگی ساخته و آزموده شد؛ ادعای بازیابی PostgreSQL تولید نیست. |
| دریافت آسان اطلاعات و مدارک | فرم مرحله‌ای و جست‌وجوی دو‌زبانه، چند فایل/عکس نسخه و حفظ متن ذخیره‌نشده در مرحله قبل تکمیل و آزموده‌اند. |
| کد ارتباطات | صف یادآوری، ترجیحات بیمار، SMTP، ربات تلگرام/اتصال Start و WhatsApp Cloud رسمی آماده‌اند؛ ارسال زنده زیرساخت می‌خواهد. |

## اقدام‌ها و اطلاعاتی که اجرای واقعی به آن‌ها وابسته است

| اولویت | کار باز | چه چیزی کم است / اقدام دقیق |
| --- | --- | --- |
| ۱ | ورود گوگل سایت و کلینیک | Google provider مرجع مشترک فعلاً خاموش است. مالک Client موجود را در Google Cloud بررسی و تنظیماتش را مستقیم در همان Supabase وارد کند؛ [راهنمای دقیق](GOOGLE_SETUP_FA.md). حساب رمزی فعلی و کاربران موجود حفظ می‌شوند. |
| ۱ | اتصال تقویم **خود پنل** | OAuth Client/API/رضایت حساب پزشکی و secretهای Calendar در runtime خصوصی. اتصال ابزار گفتگو جداگانه تأیید شده؛ credential آن وارد کد پنل نمی‌شود. |
| ۱ | اجرای دائمی backend خصوصی | محل اجرای Python، PostgreSQL با TLS، مدارک خصوصی پایدار و ingress همان‌دامنه هنوز فراهم نیست. طبق تصمیم مالک، خرید هاست/پلن انجام نمی‌شود. فایل Docker و قرارداد استقرار آماده است؛ پیش‌نمایش به backend پزشکی تبدیل نشده. |
| ۱ | برنامه مطب | روزها، بازه‌های حضوری/آنلاین، مدت ویزیت و افق رزرو باید توسط پزشک تعیین/ذخیره شوند؛ ساعت فرضی رزرو فعال نشده است. |
| ۱ | اعتبارسنجی همان‌دامنه | پس از استقرار: ورود مشترک/خروج، CSRF، ابطال نشست، مالکیت و جدایی بیماران و فایل خصوصی با داده ساختگی روی HTTPS آزموده شود؛ نه با پرونده واقعی. |
| ۲ | نصب jobهای واقعی | retry تقویم، تطبیق Google، ساخت صف و worker پیام، clearsessions و پاک‌سازی داده اختیاری در scheduler میزبان اجرا شوند؛ اکنون فقط کد/runbook هستند. |
| ۲ | فرستنده ایمیل | SMTP واقعی، فرستنده و تحویل آزمایشی کنترل‌شده. SMTP ورود/بازیابی Auth در تنظیمات مشترک و SMTP یادآوری backend باید درست تنظیم شوند. سرویس پولی یا DNS ایمیل جدید تغییر نکرده است. |
| ۲ | تلگرام یادآوری بیمار | توکن سرور، نام ربات، secret و ثبت webhook روی backend خصوصی؛ انتشار مطالب سایت و یادآوری بیمار دو مسیر کاری‌اند. اتصال/پیام واقعی این مسیر انجام نشده. |
| ۲ | واتس‌اپ | حساب Business/مجوز، قالب تأییدشده، اعتبارنامه و بررسی هزینه/شرایط واقعی. مرورگر شخصی یا API غیررسمی جایگزین نشده است. |
| ۲ | پشتیبان و بازیابی تولید | DB و فایل‌های خصوصی هماهنگ، رمزنگاری/کلید جدا، نسخه بیرونی و تمرین واقعی PostgreSQL+فایل روی محیط جدا. تمرین ساختگی فعلی فقط بخشی از روش را ثابت می‌کند. |
| ۲ | محافظت و پایش واقعی | روش اسکن/قرنطینهٔ فایل، محدودیت نرخ در ورودی، پاک‌سازی/log بدون متن پزشکی و پایش خطا در میزبان. این‌ها قبل از پرونده واقعی به محیط نهایی وابسته‌اند. |
