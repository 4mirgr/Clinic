# پنل مطب دکتر امیرهوشنگ گرامی — متخصص داخلی

نسخه در حال توسعه با Django 5.2 LTS و رابط فارسی راست‌به‌چپ. مسیر محصول `/dash/` است؛ `/dash` به آن هدایت می‌شود. برنامه مسیر `/` سایت را تصاحب نمی‌کند. هنوز روی `drgerami-md.ir` مستقر نشده است؛ فعلاً توسعه بدون خرید هاست ادامه دارد.

برای ادامه توسعه با هر AI، ابتدا [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md) و دستورهای [AGENTS.md](AGENTS.md) را بخوانید. راهنما در پایان هر مرحله همراه کد در Git حفظ می‌شود.

**[پیش‌نمایش آنلاین کلینیک](https://drgerami-md.ir/clinic/)** از صفحات واقعی برنامه و داده‌های کاملاً مصنوعی ساخته شده و پاسخ زنده آن تأیید شده است. بدون نام کاربری و رمز قابل مشاهده است. این نسخه حساب زنده، ثبت پرونده یا بارگذاری ندارد؛ [راهنمای انتشار پیش‌نمایش](deploy/preview/README.md) روش ساخت، آزمون و مرزهای آن را توضیح می‌دهد. پنل کامل Django همچنان به محل اجرای واقعی و ذخیره‌سازی خصوصی نیاز دارد.

## امکانات این نسخه

- ورود واقعی و جداگانه پزشک/مدیر و منشی؛ خروج با POST و CSRF، رمز هش‌شده و نشست ۳۰ دقیقه‌ای.
- کنترل مجوز در سرور؛ منشی نوبت‌ها و زمان‌های آزاد را مدیریت می‌کند، بدون دسترسی به اطلاعات بالینی، مدارک یا اتصال/قطع Google.
- ایجاد، ویرایش و جست‌وجوی پرونده با نام، نام خانوادگی، کد ملی و همراه. یکسان‌سازی ارقام و حروف فارسی/عربی. کد ملی اختیاری و یکتا است؛ فعلاً فقط ساختار ۱۰ رقمی بررسی می‌شود، نه رقم کنترل یا تأیید هویت.
- ثبت یادداشت‌های ویزیت به‌صورت افزایشی؛ ثبت سوابق، داروها و حساسیت‌ها.
- مدارک خصوصی PDF/JPG/PNG تا ۲۰ مگابایت؛ کنترل پسوند و امضای ابتدایی فایل، نام ذخیره‌سازی تصادفی، دریافت فقط پس از مجوز پزشک. این کنترل، اسکن بدافزار یا اعتبارسنجی کامل PDF نیست.
- کتابخانه توصیه‌ها: عنوان، متن، برچسب، منبع، وضعیت بازبینی، جست‌وجو، ویرایش و نمای چاپ با نام پزشک و QR سایت. PDF از پنجره چاپ مرورگر با Save as PDF گرفته می‌شود، نه تولید مستقیم فایل در سرور.
- ثبت رویداد مشاهده/تغییر/دریافت پرونده؛ بدون ذخیره متن شرح‌حال در رویداد.
- رابط واکنش‌گرا، حالت روز/شب با تنظیم حساب و تشخیص اولیه سیستم، فونت محلی Vazirmatn، چاپ روشن و خروجی بدون سرویس فونت یا QR خارجی.
- گرافیک اختصاصی تولیدشده با GPT ImageGen در صفحه ورود و خوشامد؛ سابقه تولید در static/clinic/art/PROVENANCE.md.
- نوبت‌دهی مدیر/منشی با تقویم بازشونده شمسی و امروز تهران، انتخاب ساعت آزاد، برنامه هفتگی و روزهای خاص. بیمار از حساب مشترک خودش وقت می‌گیرد. اتصال Google Calendar با OAuth/PKCE و تأیید ایمیل مشخص، توکن رمزنگاری‌شده و ویرایش همان رویداد با retry پایدار؛ حساب واقعی هنوز متصل نشده. راهنما در docs/GOOGLE_CALENDAR.md است.

## اجرای محلی

### ادامه توسعه بدون تهیه هاست

فعلاً توسعه در همین مخزن GitHub و محیط توسعه انجام می‌شود و به خرید سرویس نیاز ندارد. `GitHub Pages` برنامه Django را اجرا نمی‌کند؛ نسخه زنده دائمی بعداً راه‌اندازی می‌شود. حساب Google، اطلاعات بیمار و سرویس‌های تولید برای توسعه لازم نیستند.

در Linux/macOS با Python 3.12+ و `make`، از پوشه همین مخزن و در shell توسعه **بدون متغیرهای دیتابیس/اسرار تولید**:

```bash
make setup     # نصب، migration و فایل‌های استاتیک توسعه؛ SQLite محلی
make run       # http://127.0.0.1:8000/dash/
make check     # آزمون Django، migration، وابستگی‌ها و پراکسی Node
make browser   # Chromium نصب‌شده یا CHROMIUM_PATH لازم است
```

حساب پیش‌فرض یا داده جعلی در دیتابیس برنامه ساخته نمی‌شود؛ برای ورود محلی از دستور `create_clinic_user` پایین استفاده کنید. تغییرات کد روی GitHub حفظ می‌شوند و آزمون‌های موجود در Actions اجرا می‌شوند؛ نتیجه واقعی هر اجرا باید بررسی شود. پیش‌نمایش‌های منتخب با **اطلاعات کاملاً مصنوعی آزمون** در [پوشه پیش‌نمایش](docs/previews/README.md) داخل همین مخزن نگهداری می‌شوند. این تصاویر نسخه تعاملی یا لینک ورود پنل نیستند؛ هیچ `.data`، مدرک واقعی یا فایل تنظیماتی منتشر نمی‌شود. این مرحله هاست، ذخیره‌سازی artifact، سرویس پولی یا Codespace ایجاد نمی‌کند.

### ثبت توصیه برای بیمار

در پرونده بیمار، «افزودن توصیه برای بیمار» را انتخاب کنید، در متن‌های تأییدشده جست‌وجو کنید، متن کامل را بازبینی و ثبت کنید. هر ثبت یک نسخه مستقل از عنوان، متن، برچسب، منابع و زمان بازبینی نگه می‌دارد. ویرایش کتابخانه یا برداشتن تأیید، متن ثبت‌شده قبلی را تغییر نمی‌دهد. اگر متن بین پیش‌نمایش و ثبت تغییر کرده باشد، بازبینی دوباره لازم است؛ تکرار همان فرم رکورد دوم نمی‌سازد.

سابقه در پرونده پزشک و در پرتال حساب متصل به همان بیمار صفحه‌بندی می‌شود. هر نسخه چاپ/PDF مرورگر با تاریخ شمسی و QR عمومی سایت دارد؛ QR به پرونده بیمار لینک نمی‌دهد. منشی و مدیر وب‌سایت بدون مجوز پزشکی حق ثبت ندارند. این ثبت، ارسال پیام یا تأیید دریافت بیمار نیست. نسخه ثبت‌شده در رابط و `save` عادی ویرایش نمی‌شود؛ دسترسی مستقیم اپراتور پایگاه داده همچنان باید محدود باشد. پس از به‌روزرسانی، migration جدید `0009_advicedelivery` را نیز اجرا کنید.

Python 3.12+ لازم است. هر کار ابری در محیط جدا اجرا می‌شود؛ از همین checkout استفاده کنید و بدون درخواست کاربر worktree نسازید.

```bash
cd /workspace/Clinic
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate --noinput
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/python manage.py check
.venv/bin/python manage.py runserver 127.0.0.1:8000 --noreload
```

به‌صورت محلی SQLite در `.data/` استفاده می‌شود. تنظیمات توسعه برای انتشار اینترنتی مناسب نیستند. فایل `.env` خودکار توسط Django خوانده نمی‌شود؛ Docker Compose آن را به محیط فرایند منتقل می‌کند. در اجرای دستی از تنظیم متغیرها توسط سرویس/میزبان استفاده کنید.

### ساخت حساب واقعی

هیچ حساب یا رمز پیش‌فرضی ساخته نشده است. روی محل نصب نهایی، پس از migration:

```bash
.venv/bin/python manage.py create_clinic_user dr.gerami --role manager
.venv/bin/python manage.py create_clinic_user secretary --role secretary
# برای تغییر رمز:
.venv/bin/python manage.py changepassword dr.gerami
```

رمز در ترمینال به‌صورت مخفی و دوبار پرسیده می‌شود؛ حداقل ۱۲ کاراکتر و قوانین قدرت رمز اعمال می‌شوند. این دستور حساب موجود یا نقش آن را بازنویسی نمی‌کند. برای تعلیق حساب یا تغییر نقش، فقط اپراتور مجاز میزبانی از Django shell استفاده کند؛ مدیریت نقش از وب هنوز ساخته نشده است. ورود ناموفق پنج‌باره، نام کاربری را ۱۵ دقیقه محدود می‌کند؛ بازیابی رمز با ایمیل/SMS و احراز هویت دومرحله‌ای هنوز اضافه نشده‌اند.

## آزمون و اعتبارسنجی

```bash
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/python manage.py test
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python -m pip check
node --test deploy/cloudflare/worker.test.mjs
# آزمون مرورگر واقعی، با داده و حساب کاملاً موقت:
.venv/bin/python -m pip install -r requirements-dev.txt
CHROMIUM_PATH=/usr/bin/chromium .venv/bin/python manage.py test clinic.browser_checks
```

آزمون مرورگر از Chromium نصب‌شده استفاده می‌کند؛ در این محیط کانتینری با `--no-sandbox` و فقط علیه سرور تست محلی اجرا می‌شود. تصاویر و PDF نمونه در `test-results/` ذخیره می‌شوند و در git نیستند. نمونه PDF محتوای آزمایشی دارد و توصیه پزشکی واقعی نیست. آزمون مرورگر باید بارگیری واقعی CSS/فونت را هم تأیید کند؛ صفر بودن خطای JavaScript به‌تنهایی کافی نیست.

## راه‌اندازی روی دامنه با Cloudflare و Supabase

دامنه در ایرنیک ثبت شده است. Cloudflare DNS/Worker مسیر را به برنامه می‌رساند. Supabase می‌تواند PostgreSQL را تأمین کند. **این برنامه به یک محل اجرای Python یا Docker با فضای فایل ماندگار نیاز دارد؛ روی Cloudflare Pages یا Supabase به‌تنهایی اجرا نمی‌شود.** Supabase Auth و Storage در این نسخه متصل نشده‌اند؛ احراز هویت Django و فضای فایل خصوصی روی میزبان استفاده می‌شود.

۱. یک سرویس اجرای کانتینر/Python انتخاب و محل نگهداری داده پزشکی و فضای پایدار را تعیین کنید. کلیدها/رمزها را در secret manager آن میزبان وارد کنید، نه در گفتگو یا git.

۲. ترجیحاً یک پروژه/پایگاه PostgreSQL اختصاصی برای پنل بسازید. اتصال به پروژه موجود بدون بررسی جدول‌ها و مجوزها مناسب نیست؛ migrationها جدول‌های Django را ایجاد می‌کنند. برای Supabase از اتصال مستقیم یا session pooler استفاده کنید، نه transaction pooler. URL کامل اتصال و CA معتبر ارائه‌دهنده در تنظیمات امن میزبان لازم است. اتصال تولید با `sslmode=verify-full` و تطبیق نام میزبان و گواهی اجرا می‌شود؛ بررسی TLS را غیرفعال نکنید.

۳. از `.env.example` برای نام تنظیمات استفاده کنید. `DJANGO_SECRET_KEY` تصادفی ۶۴+ کاراکتر، `DATABASE_URL`، میزبان‌های مجاز و فضای پایدار لازم‌اند. هر میزبان اصلی برنامه که در Host درخواست ظاهر می‌شود باید در `DJANGO_ALLOWED_HOSTS` باشد. `DJANGO_CSRF_TRUSTED_ORIGINS` باید `https://drgerami-md.ir` را شامل شود.

۴. اگر دامنه روی Nginx همین سرور است، بخش `deploy/nginx-location.conf` را داخل server موجود HTTPS اضافه کنید؛ `location /` فعلی را عوض نکنید. Cloudflare روی Full (strict) باشد. کش `/dash` و `/dash/*` را دور بزنید. فقط به پراکسی‌ای اعتماد کنید که `X-Forwarded-Proto` را بازنویسی می‌کند و دسترسی مستقیم origin را بسته است.

۵. اگر صفحه اصلی روی Cloudflare Pages/میزبان دیگری است، Worker اختیاری `deploy/cloudflare/worker.mjs` فقط مسیرهای دقیق `/dash` و `/dash/*` را به سرویس Python بفرستد. فایل `wrangler.toml` عمداً مسیر فعال ندارد تا با پروژه‌های فعلی تداخل ایجاد نکند. `ORIGIN_URL` باید یک HTTPS origin متفاوت باشد. `CLINIC_PROXY_KEY` تصادفی حداقل ۳۲ کاراکتر را هم در secrets سرویس Python و هم Worker بگذارید؛ Worker آن را روی درخواست می‌گذارد و Django درخواست مستقیم بدون کلید را رد می‌کند. Host سرویس Python نیز در ALLOWED_HOSTS لازم است. کلید را در فایل تنظیمات Worker ننویسید. Worker با آزمون Node بررسی می‌شود؛ انتشار واقعی و آزمون در حساب Cloudflare هنوز انجام نشده است.

۶. پس از نصب، در همان محیط تولید:

```bash
python manage.py migrate --noinput
python manage.py collectstatic --noinput
python manage.py check --deploy
python manage.py create_clinic_user dr.gerami --role manager
python manage.py create_clinic_user secretary --role secretary
gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 2 --timeout 60 --forwarded-allow-ips ''
```

۷. درخواست بدون ورود به `/dash` باید به ورود هدایت شود؛ منشی با URL مستقیم پرونده هم ۴۰۳ بگیرد. دریافت فایل، ایجاد/جست‌وجوی بیمار، چاپ، خروج و بازیابی پشتیبان باید روی مقصد نهایی دوباره آزموده شوند.

بررسی `check --deploy` دو هشدار HSTS مربوط به تمام زیردامنه‌ها و preload گزارش می‌کند. این دو گزینه عمداً فعال نشده‌اند، چون وضعیت HTTPS همه پروژه‌های دیگر دامنه مشخص نیست؛ هشدارها پنهان نشده‌اند. پیش از فعال‌کردن آن‌ها باید کل زیردامنه‌ها بررسی شوند. HTTPS و کوکی Secure خود پنل در حالت تولید فعال‌اند.

### Docker

```bash
docker build -t gerami-clinic .
# در محیط دارای CA اختصاصی پراکسی، بدون غیرفعال‌کردن TLS:
docker build --secret id=build_ca,src=/etc/ssl/certs/ca-certificates.crt -t gerami-clinic .
# .env واقعی فقط در میزبان و با دسترسی محدود نگهداری شود.
docker compose build
docker compose run --rm clinic python manage.py migrate --noinput
docker compose run --rm clinic python manage.py check --deploy
docker compose run --rm clinic python manage.py create_clinic_user dr.gerami --role manager
docker compose run --rm clinic python manage.py create_clinic_user secretary --role secretary
docker compose up -d
```

کاربر کانتینر غیر root است؛ پورت compose فقط روی loopback باز است. volume `clinic_documents` باید حفظ و پشتیبان‌گیری شود. اجرای `down -v` یا حذف volume داده را از بین می‌برد؛ در راهنمای عملیات معمول استفاده نشود. فایل‌های خصوصی نباید به CDN یا مسیر عمومی رسانه متصل شوند. در سرور بدون پراکسی یا HTTPS این پیکربندی تولید را اجرا نکنید.

## کارهای باقی‌مانده و شرایط استفاده واقعی

- محل اجرای دائمی، اتصال پروژه و تنظیم مسیر Cloudflare هنوز فراهم نشده؛ انتشار، DNS و پروژه‌های فعلی تغییر نکرده‌اند.
- اتصال واقعی PostgreSQL/Supabase و گواهی آن باید در مقصد تأیید شود. آزمون محلی به معنی تأیید اتصال Supabase نیست.
- حساب‌های نهایی و رمزها باید در میزبان نهایی ساخته شوند؛ حساب‌های آزمون در دیتابیس تست موقت‌اند.
- پشتیبان‌گیری رمزنگاری‌شده و هماهنگ پایگاه‌داده و فایل، دوره نگهداری و آزمون بازیابی؛ زمان‌بندی `clearsessions` و پاک‌سازی throttleهای منقضی؛ ثبت و پایش خطا بدون داده پزشکی؛ کنترل نرخ در edge/ingress.
- پیش از فایل‌های واقعی، اسکن بدافزار/قرنطینه و سیاست ذخیره داده پزشکی باید تکمیل شوند. کنترل امضای فایل جایگزین آن نیست.
- ورود دومرحله‌ای مدیر، بازیابی امن حساب، و مدیریت نشست‌های دستگاه‌ها هنوز ساخته نشده‌اند.
- تخصیص توصیه تأییدشده به بیمار و نگهداری نسخه همان لحظه اکنون موجود است؛ نسخه‌بندی تمام ویرایش‌های میانی کتابخانه و تاریخچه کامل تغییر سایر سوابق هنوز ساخته نشده‌اند. رویدادهای audit فقط شناسه/عمل را نگه می‌دارند، نه متن پزشکی.
- ثبت‌نام/پرتال مشترک بیمار و انتخاب وقت در کد موجودند؛ صفحات حساب وب‌سایت به اتصال پراکسی نیاز دارند. محدودیت‌های بیشتر منشی، مکاتبه، تلگرام/واتس‌اپ و مشاهده‌گر DICOM هنوز پیاده نشده‌اند. اتصال زنده Calendar و نصب job retry انجام نشده است.
- تاریخ نوبت و برنامه روز خاص شمسی و ساعت تهران است؛ تاریخ سایر بخش‌های قدیمی ممکن است همچنان میلادی نمایش داده شود. ویرایش نوبت از طول ویزیت فعلی تنظیمات استفاده می‌کند. تغییر دستی داخل Google هنوز به پنل برنمی‌گردد.
- فایل قالب گوگل‌درایو هنوز به دلیل محدودیت شبکه مشاهده نشده؛ ظاهر فعلی طراحی اولیه است و تطابق با قالب ادعا نمی‌شود. اصل فایل‌های لوگو در محیط موجود نیست؛ سربرگ فعلی نام و عنوان واقعی دارد و از نشان عمومی رابط استفاده می‌کند. لوگوی نهایی هنوز نصب نشده است.
- QR به دامنه اعلام‌شده در CV اشاره دارد؛ دسترس‌پذیری محتوای سایت باید روی مقصد تأیید شود.

## منبع فونت

Vazirmatn از بسته رسمی `@fontsource/vazirmatn@5.3.0` با npm pack و کنترل integrity آن دریافت شده؛ فقط وزن‌های ۴۰۰ و ۶۰۰ عربی محلی شده‌اند. مجوز SIL Open Font License در `static/clinic/fonts/OFL.txt` نگهداری می‌شود.

### کتابخانهٔ آماده و PDF چندتوصیه‌ای

۲۴ متن فارسی تألیفی و نیازمند بازبینی، در ۱۲ شاخهٔ داخلی با عنوان/برچسب انگلیسی و فارسی در `clinic/data/advice_defaults.json` نگهداری می‌شوند. منابع NHS، NIDDK، NCI و NIA همراه تاریخ بررسی در `clinic/data/SOURCES.json` آمده‌اند. واردکردن دوباره، ویرایش شخصی پزشک را بازنویسی نمی‌کند:

```sh
.venv/bin/python manage.py migrate
.venv/bin/python manage.py load_default_advice --reviewer EXISTING_MANAGER_USERNAME
.venv/bin/python manage.py collectstatic --noinput
```

در کتابخانه چند توصیه انتخاب کنید، بیمار مقصد و متن کامل را بررسی و تأیید کنید. ترتیبِ انتخاب در مرورگر حفظ می‌شود. نسخهٔ ثبت‌شده، نام بیمار و متن/منابع همان زمان را نگه می‌دارد؛ ویرایش منبع، تأیید قبلی آن را برمی‌دارد. فرم بازبینی نیم‌ساعت اعتبار دارد. بیمار فقط نسخهٔ پروندهٔ صریحاً متصل به حساب خودش را می‌بیند.

PDF واقعی با WeasyPrint، قلم کامل محلی وزیرمتن و لوگوی اصلی سایت ساخته می‌شود؛ فونت/تصویر از اینترنت بارگیری نمی‌شود. روی Debian/Ubuntu علاوه بر requirements، `libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0` لازم است. Dockerfile آن‌ها را نصب می‌کند. `python scripts/check_education_pdf.py` با دادهٔ کاملاً مصنوعی، چندصفحه‌ای‌بودن، تعبیه فونت و QR تصویر صفحهٔ آخر را بررسی می‌کند؛ ابزارهای `poppler-utils` و requirements-dev لازم‌اند.

خلاصه پروندهٔ QR، پیش‌نویس و نسخهٔ منتشرشدهٔ جدا دارد. یادداشت‌های خصوصی شرح حال/دارو خودکار منتقل نمی‌شوند. فقط پزشک می‌تواند انتشار/توقف انتشار را انجام دهد. مقصد پیش‌فرض QR در برنامه کامل `https://drgerami-md.ir/dash/` است؛ `CLINIC_PUBLIC_URL` فقط هنگام استقرار واقعی باید با محل همان برنامه هماهنگ شود. صادرکننده عمومی آن را به `/clinic` برای **پرونده ساختگی** تنظیم می‌کند. پیش‌نمایش فعلی جایگزین سامانهٔ خصوصیِ دارای ورود نیست.
